# 04 排障

先看 broker 日志，登录、结束登录态和原因都在里面：

```bash
tail -n 30 ~/.jms-mcp/broker.log
node src/cli.js status
```

## 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动时报 `jms-mcp 配置无效` | 配置字段缺失或格式不对 | 报错会列出全部问题：`id` 不是 UUID、`defaultAccount` 是特权账号、`ttlHours` 超过 24 等，逐条改 |
| 弹窗没出现，调用卡住后失败 | 客户端在 SSH 会话或无桌面环境里启动 | 在本机桌面里打开客户端；检测到 SSH 会话会直接报错而不是卡住 |
| macOS 弹窗被遮住 | 弹窗在其他窗口后面 | 在程序坞或「调度中心」里找 `osascript` |
| Windows 报未找到 pinentry | 没装 Git for Windows | 安装后重试，或在配置里设 `pinentryPath` 指向 `pinentry-w32.exe` |
| 弹窗顶部出现「⚠️ 密码不正确，还剩 N 次机会」 | 密码输错，弹窗已让你重输 | 确认密码后重输。输入框不显示字符，注意键盘大小写和输入法；N 低于 3 时会停止当场重输 |
| 弹出「JumpServer 登录失败」提示框 | 密码或动态码连续输错，或网络等原因 | 提示框里写了原因和下一步。**不要连续试**，密码次数用完可能触发账号锁定，锁定时间由部署策略决定 |
| 弹窗消失了，AI 说「窗口等待 N 分钟无人输入，已自动关闭」 | 超过等待时长没有输入（密码 5 分钟、动态码 2 分钟） | 让 AI 重新发起即可。macOS 会有一条「JumpServer 登录窗口已超时」的通知 |
| Codex 提示 MCP 工具调用超时，登录弹窗刚出来就被取消 | Codex 的 `tool_timeout_sec` 默认 60 秒，比弹窗等待短 | 在 `~/.codex/config.toml` 的 `[mcp_servers.jms]` 里加 `tool_timeout_sec = 1500` |
| 弹窗样式是系统最简陋的那种，没有图标和加粗标题 | AppKit 弹窗起不来，退回了 `display dialog` | 设 `JMS_MCP_DEBUG=1` 启动，看 stderr 里「AppKit 弹窗失败」后面的原因 |
| `MFA 验证失败` | 动态码输错、已过期，或同一个码用了两次 | 等验证器刷新出新的动态码再输；确认电脑时间准确 |
| `登录失败: …` 后面是别的提示 | 服务端有额外登录规则 | 把原文发给 JumpServer 管理员 |
| `无法连接 JumpServer` | 网络不通 | 确认本机能访问部署方提供的 JumpServer 入口；注意 Node 的 `fetch` 默认**不读取** `http_proxy` 等代理环境变量，JumpServer 域名需要能直接访问 |
| `JumpServer 里没有授权给你的资产` | 权限没给，或配置里的资产名与 JumpServer 里不一致 | 在 JumpServer「我的资产」里核对名称与授权 |
| `资产 X 上没有授权给你的账号 Y` | 账号没授权给你 | 看报错里列出的已授权账号，改配置里的 `accounts`，或联系管理员授权 |
| `KoKo 仍要求 MFA 验证，连接令牌没有生效` | JumpServer 对该资产或账号设置了「连接时需要 MFA」之类的规则 | 联系管理员确认登录规则，AI 不要尝试绕过 |
| `KoKo 主机指纹校验失败` | 网络不通，或 KoKo 更换了证书 | 先排除网络；指纹确实变了，由管理员确认新指纹后再改 `hostKeySha256`，不要为了通过而随手改 |
| `主机名核对失败` | 资产配错，或同名资产指到了别的机器 | 在 JumpServer 里确认资产，必要时在配置里写上正确的 `id` |
| 命令超时但远端进程还在 | 资产没有 `timeout`/`bash`，或远端没按时结束 | 看返回的 `note`；手动在服务器上确认并清理进程 |
| `jms_list` 提示 broker 是旧代码 | 更新代码后旧 broker 还有登录态 | 登录态结束后会自动换新；也可直接 `cli.js stop` |
| 改了配置不生效 | broker 还在用旧配置 | `node src/cli.js stop`，再让 AI 调用一次 |

## 登录态意外结束

`broker.log` 里会记录登录和结束的时间与原因：

| 日志 | 含义 |
|---|---|
| `已登录 <用户>，有效期至 …` | 登录成功，括号里是到期时间 |
| `登录态已结束 <用户>: 到达有效期` | 正常到期，下一次调用会重新弹窗 |
| `登录态已结束 <用户>: 手动注销` | 执行过 `jms_logout` 或 `cli.js stop` |
| `登录态已结束 <用户>: 登录态已失效` | JumpServer 判定登录态无效（管理员强制下线、改密码等），已自动重新登录 |
| `退出: 无活动连接且空闲超时` | 没有登录态时 broker 空闲 10 分钟自己退出，正常 |

网络波动、电脑睡眠**不会**让登录态失效，只会让当时那条命令失败。

## 收回授权

任何时候想让登录态立即失效：

```bash
node src/cli.js stop
```
